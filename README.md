# 采集调度策略管理工具

离线版采集调度策略配置工具，涵盖站点登记、模板编排、代理轮换、限速调节、反爬策略、增量水位与结果校验规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts          本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/orchestration-service.ts  依赖编排、清单发布/接收、落盘、复核、轨迹
│   ├── src/domain/pipeline.ts            纯函数编排内核：依赖校验、波次、批次视图、核对
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 采集流水线依赖编排

| 页面 | 能力 |
| --- | --- |
| 采集流水线 `/pipeline` | 读取步骤的输入数据源、处理逻辑、输出目标、依赖步骤；校验编号唯一、字段齐全、依赖存在、无自依赖、无环路、上游已启用；按波次生成就绪批次并发布清单；批次视图展示依赖与输入状态；步骤编号查询入口；冲突边界比对；核对条件回查 |
| 数据落盘 `/storage` | 接收清单后同步待处理清单；按波次释放下一批输出文件，未就绪步骤不预留路径；串行策略独占写入，并行策略末步合并；冲突复核、当天处理轨迹、存储配置登记 |
| 运营概览 `/` | 按波次排列流水线就绪批次概览，标出输入未完整的步骤 |

关键规则：

- **不生成半张计划**：依赖校验有任何问题（环路、缺失输入、未知依赖、上游未启用、无可运行步骤）时
  `planDraft()` 返回完整问题清单且 `plan === null`，页面不会写入清单版本。
- **一次发布一份快照**：依赖图、步骤状态、就绪批次与核对结果同一次写入 `manifest`，版本号 +1；
  旧版本标记为「已替代」，数据落盘已接收的那份不会自动跟随，需要显式「接收」。
- **按批次释放**：只有上一批次全部步骤都产出文件后，下一波次才会被释放；未就绪步骤的目标路径
  不预留。重复扫描同一份登记不会把同一步骤放进两个批次。
- **两种写入方式**：输出目标重合且依赖允许并行时，「按输出目标冲突串行执行」会把后写步骤推到下一波，
  产生多个串行文件版本；「允许并行并在末步合并文件」让两步同波并行写分片，末步合并为最终版本。
  复核固定以冲突串行口径为依据。
- **失败接着完成**：记录采集流水线处理失败后不产出新清单，落盘沿用上一份已确认版本继续，
  失败按串行口径写入当天处理轨迹。

纯函数内核可以直接在终端里跑（需要 Node ≥ 22.6）：

```bash
cd frontend
npm run check:orchestration
```

也可以起 dev server 后手工走一遍：`/pipeline` → 选择策略 → 发布清单 → `/storage` → 接收 → 逐批落盘 → 冲突复核。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-strategy-studio:entries` 这一项，或调用 `resetModule(模块)`。
